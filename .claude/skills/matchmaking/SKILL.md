# マッチメイク（matchmaking）

## 目的
選手とマネジメントが「次にどの相手を狙うか」「来たオファーを受けるか」を決めるために、ランキング、階級内の予定、団体のマッチメイクの傾向を揃える。
結論は選択肢と条件までとし、最終判断は選手とマネジメントが行う。

## 選手コンテキスト
1. `profile.md` を読む。使う項目: 所属団体、階級、契約状況（残り試合数）、戦績 URL、次戦、追跡したい選手、目標。
2. 引数に相手名があれば「オファー評価」モード。なければ「階級状況」モード。
3. `outputs/fighter-tracker/` の直近ファイルがあれば読み、階級内の最新の動きを前提にする。
4. `inputs/matchmaking/` にファイルがあれば読む（マネジメント経由で聞いた団体側の意向など。区分は「本人メモ」）。

## 収集手順
### 階級状況モード
1. 情報源 1 で現在のランキング（王者、1〜15 位）と自分の順位を取る。
2. 情報源 2 で上位 15 名の次戦の有無（発表済み / 未定）を取り、「組まれていない選手」を抽出する。
3. 情報源 4〜5 で、団体の方針（階級の活性化、特定選手の売り出し、タイトル挑戦者決定戦の予定）を取り、区分を付ける。
4. 自分の順位、戦績、残り試合数と照らし、現実的に組まれ得る相手を「上の相手（勝てば順位が上がる）」「同格」「下の相手（負ければ大きく下がる）」に分けて列挙する。
5. 判断への接続: どの層を狙うか、マネジメント経由で名乗りを上げる相手、断る相手の条件。
### オファー評価モード
1. 相手の順位、戦績、次戦の有無、計量失敗歴を情報源 1〜2 で取る。
2. 勝った場合と負けた場合の順位・契約への影響を、ランキング算出方法（情報源 1）と過去の類似事例（情報源 5）から推定し、区分「推定」で書く。
3. 準備期間（オファーから試合日まで）と、profile.md の減量履歴・負傷歴から、受けられる条件を書く。weight-cut の実行を促す。
4. 判断への接続: 受ける条件（報酬、日程、相手変更時の扱い）、断った場合に団体との関係へ及ぶ影響（報道事例から推定）。
### 共通
- 出力を `outputs/matchmaking/YYYY-MM-DD-<件名>.md` に保存する。

## 出力テンプレート
```markdown

モード: [階級状況 / オファー評価]

## 結論
- [狙う層 / 受けるか] — [1 行の理由]

## ランキング（確定情報）
| 順位 | 選手（原語） | 戦績 | 次戦 | 出典（取得日） |
|---|---|---|---|---|

## 団体の方針（報道）
- [発言・報道] — 出典（日付）

## 組まれ得る相手
| 層 | 選手 | 根拠 | 区分 |
|---|---|---|---|
| 上 / 同格 / 下 | | | 確定情報 / 報道 / 推定 |

## 勝敗による影響（推定）
- 勝った場合: [順位・契約への影響] — 算出根拠
- 負けた場合: [同上]

## 噂・未確認
- [内容] — 出典。確認方法

## この情報で変わり得る判断（1〜3 点）
1. [狙う相手 / オファーの可否] — 受ける条件 / 断る条件
2. [マネジメントに依頼すること]
3. [報酬条件 → contracts-pay で確認]

## 鮮度
- 再確認が必要になる条件: ランキング更新、上位者の試合発表・結果、団体の階級再編
```

## 更新頻度
週次（ランキング更新に合わせる）。オファーが来た時点で随時。スケジュール実行の対象（`docs/DECISIONS.md` D-1）。

## 禁止事項
- マッチメイカーの意図を発言の出典なしに書かない。発言がない場合は「推定」と区分する。
- ランキング変動の予測を確定情報の文体で書かない。
- 相手の私生活や未公表の負傷を判断材料に使わない。
- 固有名詞は原語を併記する（例: タイトル挑戦者決定戦（title eliminator））。
