## D-1. スキルとサブエージェントの使い分け基準

### 前提（Claude Code の仕組み）
- **スキル**（`.claude/skills/<name>/SKILL.md`）は、呼び出された時点で本文が**現在の会話のコンテキストに読み込まれる手順書**。会話の履歴（選手プロファイル、直前の相談内容）をそのまま使え、結果もそのまま会話に残る。
- **サブエージェント**（`.claude/agents/<name>.md`）は、**独立したコンテキストで動く別の実行単位**。親の会話履歴を持たず、親に返るのは最終報告のみ。途中のツール呼び出し結果は親のコンテキストを消費しない。使えるツールとモデルを個別に制限できる。
- スキルの frontmatter に `context: fork` を指定すると、スキルの手順をサブエージェントとして実行できる。入口はスキル、実行はサブエージェント、という組み合わせが可能。ただし fork されたスキルは会話履歴を見られないため、選手名などの入力は `$ARGUMENTS` で受け取り、プロファイルは自分で読む自己完結の手順にする必要がある。
- ツールの制御は 2 種類ある。スキルの `allowed-tools` は「確認なしで使える」許可の事前付与であり、他のツールを禁止しない。使えるツールを狭めるのは、スキルでは `disallowed-tools`、サブエージェントでは `tools`（許可リスト）または `disallowedTools`。
- サブエージェント定義の `skills` に共通スキル名を列挙すると、その内容が起動時に注入される。共通規約（出力形式、プロファイルの読み方）を複数の調査役で共有する手段になる。

出典: https://code.claude.com/docs/en/skills.md 、 https://code.claude.com/docs/en/sub-agents.md 、 https://code.claude.com/docs/en/memory.md （取得日 2026-10-17）

### 基準
既定はスキル。次のいずれかに当たるときだけサブエージェント（または `context: fork` 付きスキル）にする。

| 条件 | 理由 |
|---|---|
| Web 取得や長文資料の読み込みが多く、中間結果が会話を圧迫する（目安: ツール呼び出し 10 回超、または取得テキストが数万字） | 親のコンテキストを汚さず、要約だけ受け取れる |
| 複数の調査を**同時並行**で走らせたい（例: 対戦相手 3 名の比較） | サブエージェントは並列実行できる |
| 使えるツールを**狭める必要**がある（例: ファイル書き込み禁止の調査専用） | サブエージェントの `tools` またはスキルの `disallowed-tools` で禁止できる |
| 安価・高速なモデルで十分な定型処理 | `model` を個別に指定できる |

逆に、次の性質を持つものはスキルのまま置く。
- 会話中の文脈（トレーナーの直前の問い、既に出た結論）を前提にする。
- 出力が短く、トレーナーがその場で読んで次の問いを続ける。
- 選手プロファイルの読み方や出力形式など、**他のスキルから共通に使われる規約**。

### 運用規則
1. 26 スキルはすべて `.claude/skills/` にスキルとして置く。トレーナーから見た入口は常にスキル名で統一する。
2. 上の表の条件に当たるスキルは `context: fork` を付け、必要なら `disallowed-tools` で範囲を絞る。fork するスキルは選手名を `$ARGUMENTS` で受け取り、プロファイルを自分で読む。別ファイルのサブエージェント定義は、複数スキルから共用する調査役（例: 試合結果取得、ルール照会）に限って `.claude/agents/` に置き、`skills` に共通規約スキルを指定する。
3. 初期実装では全スキルを `context: fork` なしで書き、実際に会話が圧迫されたものから順に fork に切り替える。先に分けない。

## D-2. 実行環境

### 選択肢
| 環境 | 長所 | 短所 |
|---|---|---|
| A. Claude Code CLI（トレーナーの手元の端末） | 設定不要。ローカルの `profiles/` と `outputs/` を直接読み書き。commit まで一続き | 端末がないと動かない |
| B. Claude Code on the web（クラウドセッション） | 端末不要。スマホからも起動できる。長時間の調査を任せられる | 外部サイトへの到達可否が環境のネットワーク設定に依存。成果物は commit/push しないと消える |
| C. Agent SDK で独自アプリ化 | UI を自由に設計できる | 実装・運用コストが大きい。スキルが固まる前に作ると作り直しになる |

### 決定
- **主環境は A（Claude Code CLI）**。リポジトリを clone して開けばスキルが自動で有効になる。
- **B はスキルとリポジトリが同じ形で動く**ため、長時間調査や外出時の利用に併用する。B で使う場合は、スキルが参照する外部サイト（試合結果、団体公式、ルール文書）への到達をクラウド環境のネットワーク設定で許可しておく。
- **C は保留**。26 スキルの出力形式と使用頻度が実運用で安定した後に判断する。

### 環境に依存しないための規約
- スキルは**ファイルパスをリポジトリ相対**で書く（`profiles/`, `outputs/`）。絶対パスを書かない。
- 外部情報の取得は `WebSearch` / `WebFetch` に限定し、特定の API キーを要する取得手段をスキル本体に埋め込まない。必要になった場合は別途 `docs/` に接続手順を記録する。
- 成果物（分析結果）は REQUIREMENTS.md 第 4 節の置き場所に Markdown で保存し、A・B どちらで作っても同じ場所に commit する。
