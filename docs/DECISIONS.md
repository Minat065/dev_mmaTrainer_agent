## D-1. スキルとサブエージェントの使い分け基準

### v0.1 の仮置きに対する結論
仮置きは「単発の調べ物 = スキル、定期巡回 = エージェント」だった。この区別は Claude Code の仕組みと噛み合わない。
- **定期巡回**は「いつ実行するか」の問題で、スケジュール実行（Claude Code のスケジュールタスク、またはクラウドセッションの定期実行）が担う。実行されるものはスキルでよい。
- **サブエージェント**は「どのコンテキストで実行するか」の問題で、会話を汚さずに大量のツール呼び出しを済ませたいときの手段。

したがって、26 本はすべてスキルとして書く。定期巡回が必要なもの（`fighter-tracker`、`matchmaking`、`rules`、`anti-doping`、`promotions`）は、スキルをスケジュール実行し、結果を `outputs/` に書き出す。

### 前提（Claude Code の仕組み）
- **スキル**（`.claude/skills/<name>/SKILL.md`）は、呼び出された時点で本文が現在の会話に読み込まれる手順書。会話の履歴（`profile.md` の内容、直前の相談）をそのまま使え、結果もそのまま会話に残る。
- **サブエージェント**（`.claude/agents/<name>.md`）は、独立したコンテキストで動く別の実行単位。親の会話履歴を持たず、親に返るのは最終報告のみ。途中のツール呼び出し結果は親のコンテキストを消費しない。
- スキルの frontmatter に `context: fork` を指定すると、スキルの手順をサブエージェントとして実行できる。fork されたスキルは会話履歴を見られないため、入力は `$ARGUMENTS` で受け取り、`profile.md` は自分で読む自己完結の手順にする必要がある。
- ツール制御は 2 種類ある。スキルの `allowed-tools` は「確認なしで使える」許可の事前付与であり、他のツールを禁止しない。使えるツールを狭めるのは、スキルでは `disallowed-tools`、サブエージェントでは `tools`（許可リスト）または `disallowedTools`。
- サブエージェント定義の `skills` に共通スキル名を列挙すると、その内容が起動時に注入される。

### 基準
既定はスキル（fork なし）。次のいずれかに当たるときだけ `context: fork` を付ける。

| 条件 | 理由 |
|---|---|
| Web 取得や長文資料の読み込みが多く、中間結果が会話を圧迫する（目安: ツール呼び出し 10 回超） | 親のコンテキストを汚さず、要約だけ受け取れる |
| 複数の調査を同時並行で走らせたい（例: 対戦候補 3 名の比較） | fork されたスキルは並列実行できる |
| 使えるツールを禁止したい（例: ファイル書き込み禁止の調査専用） | `disallowed-tools` で禁止できる |
| 安価・高速なモデルで足りる定型処理 | `model` を個別に指定できる |

### 運用規則
1. 初期実装では全スキルを fork なしで書く。実運用で会話が圧迫されたものから順に `context: fork` に切り替える。先に分けない。
2. 別ファイルのサブエージェント定義（`.claude/agents/`）は、複数スキルから共用する調査役（例: 試合結果の取得）が必要になった時点で作る。初期実装では作らない。

## D-2. 実行環境

### 選択肢
| 環境 | 長所 | 短所 |
|---|---|---|
| A. Claude Code CLI（手元の端末でこのリポジトリを開く） | `profile.md`・`inputs/`・`outputs/` を直接読み書きし、結果を commit できる。設定不要 | 端末が要る |
| B. Claude Code on the web（クラウドセッション） | 端末不要。長時間の調査やスケジュール実行を任せられる | 外部サイトへの到達可否がネットワーク設定に依存。commit しないと結果が消える |
| C. Claude.ai のカスタムスキル（SKILL.md を zip で登録） | スマホの Claude アプリから使える | `profile.md` や `outputs/` を読み書きできない。出力が会話に閉じる |
| D. Agent SDK で独自アプリ化 | UI を自由に設計できる | 実装・運用コストが大きい。スキルが固まる前に作ると作り直しになる |

### 決定
- **主環境は A**。B はスケジュール実行と長時間調査に併用する。A と B は同じリポジトリ、同じファイル構成で動く。
- **C は補助**。SKILL.md の形式は Claude.ai のカスタムスキルと互換なので、外出先で読むだけの用途には各スキルのフォルダをそのまま zip で登録できる。ただし `profile.md` を読めないため、C で使うときは選手コンテキストを会話で渡す。
- **D は保留**。26 スキルの出力形式と使用頻度が実運用で安定した後に判断する。

### 置き場所を `.claude/skills/` にした理由
Claude Code がプロジェクトのスキルを自動で読み込むのは `.claude/skills/` だけ。v0.1 の `skills/` はプラグイン形式の配置で、プラグインとして登録しないと読み込まれない。このリポジトリ自体が作業場所（`profile.md` と `outputs/` が同居する）なので、開けば使える `.claude/skills/` を選んだ。

### 環境に依存しないための規約
- スキル内のパスはリポジトリ相対で書く（`profile.md`、`inputs/`、`outputs/`）。
- 外部情報の取得は `WebSearch` / `WebFetch` に限定する。API キーを要する取得手段をスキル本体に埋め込まない。

## D-3. `profile.md` の項目定義

単一ファイル `profile.md` をリポジトリ直下に置く。項目は以下。実体と記入例は `profile.md` 本体を参照。

| 区分 | 項目 | 主に使うスキル |
|---|---|---|
| 基本 | 氏名・リングネーム、生年月、所属団体、契約状況（残り試合数・満了日）、階級（契約体重）、身長・リーチ・スタンス、所属ジム・ヘッドコーチ、マネジメント | 全スキル |
| 体重 | 通常体重、直近 3 試合の減量履歴（開始→計量→試合当日）、過去の計量失敗 | `weight-cut`、`nutrition` |
| スタイル | ベース競技、強み・弱み、直近の敗因 | `opponent-scouting`、`tactical-meta`、`technique` |
| 次戦 | 相手、日程、会場、開催地コミッション、ルールセット、計量から試合開始までの時間 | `weight-cut`、`opponent-scouting`、`rules`、`judging-refereeing` |
| 履歴 | 戦績ページ URL（Sherdog / Tapology）、負傷歴 | `fighter-tracker`、`injury-medicine`、`longevity` |
| 制約 | 医療上の制約、服薬・サプリ、使える有料ソース | `anti-doping`、`weight-cut`、全スキル（D-4） |
| 関心 | 追跡したい選手、目標（タイトル、移籍、引退時期） | `fighter-tracker`、`matchmaking`、`finance-retirement` |

規則:
- 各スキルは実行の最初に `profile.md` を読み、必要な項目が空なら推測で埋めず、空であることを出力に明記する。
- `profile.md` は選手の個人情報を含む。このリポジトリを公開にする場合は `.gitignore` に移し、`profile.example.md` だけを残す。

## D-4. 情報源への到達手段

### 決定
- **自動で取得するのは、Web 検索と公開ページに限る**。団体公式、コミッション公式、論文（PubMed、出版社）、公開の記録サイト（Sherdog、Tapology、UFCStats、Fight Matrix）、報道。
- **有料ソース（UFC Fight Pass、有料記事、放送）はスキルが自動で取得しない**。利用規約の問題と、認証情報をスキルに持たせない方針のため。
- 有料ソースや映像から得た情報は、選手またはコーチが**人手でメモにして `inputs/<skill-name>/` に置く**。スキルはそれを読み、出典を「本人メモ（視聴元: Fight Pass、試合名）」として記す。
- 選手・関係者の SNS 発信は取得してよいが、区分は「当事者発信」とし、団体公式の確認が取れるまで「確定情報」にしない。

### 情報の区分（共通要件 2 の実装）
| 区分 | 定義 | 例 |
|---|---|---|
| 確定情報 | 団体・コミッション・当事者本人の公式発表、査読論文、公的記録 | 公式戦績、公式ルール文書、計量結果の公式発表 |
| 報道 | 実名メディアの記事で、公式発表がまだないもの | 契約交渉中の報道、移籍報道 |
| 噂 | 匿名ソース、SNS の未確認投稿、まとめサイト | 「次戦は○○らしい」 |
| 推定 | 公開データから第三者が計算した値 | 推定ファイトマネー、Elo 系レーティング |

## D-5. 出力の保存先

- 実行結果は `outputs/<skill-name>/YYYY-MM-DD-<件名>.md`。件名は英数字とハイフン（例: `2026-10-17-weight-cut-plan-nov-event.md`）。
- 定期巡回スキルは日付のみ（`outputs/fighter-tracker/2026-10-17.md`）。前回との差分を冒頭に書く。
